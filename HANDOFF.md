# Free Scribe — where things stand

Context for picking this up in a fresh session. Written 21 Aug 2026.

## What it is

Local dictation. Hold a shortcut, speak, release, and the text is typed into
whatever app you were in. Everything runs on the machine — no cloud, no
subscription, nothing transmitted after the model download. MIT licensed, open
source, not for financial gain.

It exists partly for a specific case: a **scribe mode** implementing the NAPLAN/NESA
rules for the Writing test, so a student entitled to a scribe can dictate under the
same constraints a human scribe works to.

Repo: <https://github.com/April-sus/free-scribe> (private)

## Layout

```
core/        Swift package: scribe rules, filler cleanup, history, search, stats,
             language list, model selection. Shared by macOS and iOS. 71 tests.
macos/       Swift + SwiftUI menu-bar app. Whisper via WhisperKit (CoreML). Works.
windows/     Tauri app (Rust + web UI). Whisper via whisper.cpp. Builds, runs.
             core/ there is the Rust port of the same logic, with matching tests.
ios/         App + keyboard extension. Generated by XcodeGen from project.yml.
             App records and transcribes, keyboard inserts. See the iOS section.
translator/  Rust translation sidecar, shared by macOS and Windows.
docs/        scribe-rules.md is the behaviour contract both platforms owe.
scripts/     generate-notices.py, parity.sh
```

## State by platform

**macOS — working and in daily use.** Menu bar, floating pill, four dictation
styles, permanent transcript history with search and audio re-transcription,
usage stats, sound cues, translation.

**Windows — builds and runs**, but well behind: no history, audio cache, sounds,
search, confirmations or translation. Installers are built by CI (Actions →
Windows installer → artifacts), needing no toolchain on the target machine.

**iOS — dictation works on device.** The app holds the microphone and the model;
the keyboard lists what was dictated and types it. Verbatim only so far.

## Decisions worth not relitigating

**Everything is local.** No network after model download. This is the product.

**Behaviour must match across platforms**, especially the scribe rules — a school
must get identical transcripts whichever build it runs. `scripts/parity.sh` diffs
the two real binaries; both test suites carry the same cases under the same names.

**One translator, not two.** Apple's Translation framework was used and then
removed: it covered 22 languages against MADLAD's 98 and made macOS and Windows
disagree. MADLAD-400 3B (Apache-2.0) now handles everything, 2.8GB, ~1s per
dictation. NLLB and TowerInstruct are better known and both **CC-BY-NC** — they
would contradict the MIT licence.

**The translator is a separate process**, not a linked library: CTranslate2 is C++
and putting that inside a Swift package is far more trouble than spawning a child.
Does not work on iOS, which has no subprocesses.

**Scribe mode never reaches a language model.** Anything that could suggest a word
is a breach of the rules. Hard-wired, with tests.

## Gotchas that cost real time

- **The simulator lies.** It reports the host Mac's hardware (48GB/492GB, so the
  storage tiering picked the largest model) and overstates memory by ~2x. It also
  ran a Mac-only sysctl happily that crashed instantly on a device.
- **CI can pass for the wrong reason.** The iOS build went green on a runner whose
  Xcode had no FoundationModels at all — the code was compiled out, not checked.
- **A keyboard extension is sandboxed apart from its own app.** Anything the app
  downloads is invisible to it. They share an app group container now — and an
  extension cannot record audio in it, or anywhere else.
- **Hardened runtime needs the audio-input entitlement** or macOS denies the
  microphone silently, with no prompt, forever.
- **Whisper hallucinates on silence** — a muted mic reliably produced "you". There
  is an energy gate, calibrated against a real microphone (quiet speech peaks near
  0.016) rather than synthesised audio (0.19), which was the first mistake.
- **Whisper returns nothing for very short clips.** They are padded to two seconds.
- **One AVAudioEngine does not survive a sleep.** macOS re-enumerates audio devices
  on wake, and an engine built against the old one either refuses to start or
  delivers silence — which the energy gate then discards as nothing said, so the app
  looks broken until it is restarted. `Recorder.reset()` rebuilds it, on
  `AVAudioEngineConfigurationChange` and on `NSWorkspace.didWakeNotification`.
- **"This current action is not allowed" was our own intent failing.** Without
  keyboard dictation armed, the mic stream existed only while the app was on screen,
  so the log read Listening → Transcribing → *nothing to record into* on a loop —
  every other press failed. The failing press threw `needsToContinueInForegroundError`,
  whose confirmation defaults on, and iOS reported that as "not allowed". Now a press
  that starts with the app in front arms the keyboard window too (it closes itself
  after `sessionMinutes`), and on iOS 26 the intent declares
  `supportedModes = [.background, .foreground(.dynamic)]` and calls
  `continueInForeground(alwaysConfirm: false)` instead of throwing.
- **The Mac shortcut sometimes needed two presses.** `Hotkey` kept a `latched` flag
  of its own and set it on every tap, even when the recording had failed to start.
  The next press then took the "stop" branch, found nothing recording, and did
  nothing. The hotkey now asks `AppState.isRecording` (the recorder) instead.
- **The Action button cannot be held.** `AVCaptureEventInteraction` does report the
  button going down and coming up, and the Action button is one of the buttons it
  covers — but it was tried here with an audio-only `AVCaptureSession` running in the
  foreground and **no event of any phase ever arrived**; iOS kept the press and showed
  "this action is not allowed". The documented gate (foreground, *and* an active
  capture session) means a camera. Dictation from the button is therefore a Shortcut,
  which gives one trigger and no release: press to start, press to stop. Hold-to-talk
  exists only on the keyboard's own microphone button, which gets real touch events.
- **A vocabulary prompt can empty the transcription outright.** WhisperKit 0.18
  honours an end-of-text sampled while the prompt is still being forced, so a
  prompted decode can return "" for twelve seconds of clear speech — every dictation
  on the phone said "nothing could be made out" because of one word in the list
  (argmaxinc/WhisperKit#372; fixed upstream in #514, after the v1.0.0 tag, so the
  pin does not have it). `Transcriber.transcribe` decodes again without the prompt
  when a prompted result is empty; the biasing is lost for that dictation, the
  dictation is not. Reproduce with `LiveModelTests` and a `vocabulary.json` present.
- **A dead device looks exactly like silence.** After a sleep the engine can start
  and deliver no buffers at all. `Recorder` now counts what arrives: a second of
  recording with nothing delivered is treated as a dead device, the engine is
  rebuilt on the spot, and `lastRecordingWasDead` lets the app say so — instead of
  "didn't catch that", which sent people pressing twice.
- **Closing the lid is not always a sleep.** With an external display the Mac often
  sleeps only its screens; the audio devices still move, but `didWakeNotification`
  never fires. `screensDidWakeNotification` is observed as well.
- **Do not construct a `Recorder` in a test.** Touching `inputNode` wants a real
  device and microphone permission; in the test process it hangs rather than failing,
  and takes the whole suite with it.
- **M2M-100 had no fast tokenizer**, so the tokenisation was hand-written and
  checked against the Python reference. MADLAD ships one, so that code is gone.

## iOS: what the shape of it turned out to be

Two things were wrong, and the second one changed the design.

**The "compile the model with Xcode or MLModel.compileModel" error was a truncated
download, not a compilation problem.** On the phone `AudioEncoder.mlmodelc` had its
weights (15.7 MB) but no `model.mil`. An `.mlmodelc` missing that file looks to
CoreML like a model that was never compiled. `isDownloaded` only checked that the
folder existed, so the half-download counted as finished forever, and the app hid
the failure behind `try?` while reporting "model loaded". It now checks for
`coremldata.bin`, `model.mil` and `weights/weight.bin` in each of the three
`.mlmodelc` bundles, and an incomplete one re-downloads. Extensions compile CoreML
models perfectly well — the keyboard's own container has the `e5rt` ANE bundles to
prove it.

**An app extension cannot record audio. At all.** Apple's QA1872 says so, and the
phone agrees: with Full Access on, microphone permission `"grnt"`, the built-in mic
in `availableInputs` and `isInputAvailable` true, `AVAudioEngine.start()` fails at
`PerformCommand(*ioNode, kAUStartIO)` with 2003329396 — under `.record`,
`.record` + mix, `.playAndRecord`, and `.playAndRecord` + mix alike. There is no
session configuration that works, because none of them can.

So iOS is shaped differently from macOS, and has to be:

- **The app records and transcribes.** Hold the microphone, speak, release.
- **The keyboard drives it.** Hold its microphone and it posts a Darwin
  notification; the app cuts that stretch out of the stream it is already holding,
  transcribes it, writes it to the shared container and signals back; the keyboard
  types it. The keyboard also lists recent transcripts to tap.

So there is no app switch per dictation — only one visit to arm the microphone,
which the app now does for itself on every launch. If iOS has reclaimed the app the
keyboard says so and offers to launch it. Nothing else avoids that: an extension
cannot start its container app in the background, and the alternatives all need a
server, which would end the local-only promise.

The iOS app carries the Mac's settings, history with search, statistics,
recordings and re-transcription, every dictation style including scribe mode, and
per-model downloads. It cannot carry **translation** — that is a separate program
the app runs alongside itself, and iOS has no subprocesses — or **microphone
choice**, which iOS does not offer, or **pasting**, which is the keyboard's job.

## Still worth doing on iOS

- Dictation styles, above all **scribe mode** — iOS inserts verbatim today, and the
  scribe rules are the reason the project exists.
- A way back to the app from the keyboard. `openURL` is unofficial for keyboards;
  worth a try for sideloaded builds, not for the App Store.
- `Diagnostics.log` writes to the shared container because an extension's console
  output goes nowhere. `Diagnostics.tail()` prints it back through the app, which is
  how the keyboard was debugged — `devicectl process launch --console` shows it.
  Note `devicectl device info files --domain-type appGroupDataContainer` listed a
  *different, empty* container than the one the app actually uses; it lied for half
  an hour. Trust the path the app logs.

## How to verify things

```bash
cd core && swift test                      # 71 tests, the shared logic
cd macos && ./build.sh && open 'Free Scribe.app'
cd windows && cargo test                   # the Rust port, same cases
./scripts/parity.sh                        # diffs the two real binaries
```

Headless checks on the macOS binary, no microphone needed:

```bash
'./macos/Free Scribe.app/Contents/MacOS/FreeScribe' --transcribe file.wav
'./macos/Free Scribe.app/Contents/MacOS/FreeScribe' --clean "um so like hello"
'./macos/Free Scribe.app/Contents/MacOS/FreeScribe' --translate "Hello there" lv
'./macos/Free Scribe.app/Contents/MacOS/FreeScribe' --devices
```

iOS, with the phone unlocked and connected:

```bash
cd ios && xcodegen generate
xcodebuild -project FreeScribe.xcodeproj -scheme FreeScribe \
  -destination 'platform=iOS,id=<device-id>' -allowProvisioningUpdates build
xcrun devicectl device install app --device <device-id> <path>/FreeScribe.app
xcrun devicectl device process launch --device <device-id> --console local.freescribe.FreeScribe
```

The app logs its readings with an `[free-scribe]` prefix, so the console gives you
the numbers without reading them off the phone.
