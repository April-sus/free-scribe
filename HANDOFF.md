# Free Scribe — where things stand

Context for picking this up in a fresh session. Written 21 Aug 2026.

## What it is

Local dictation. Hold a shortcut, speak, release, and the text is typed into
whatever app you were in. Everything runs on the machine — no cloud, no
subscription, nothing transmitted after the model download. MIT licensed, open
source, not for financial gain.

It exists partly for a specific case: a **scribe mode** implementing the NAPLAN/NESA
rules for the Writing test, so a student entitled to a scribe can dictate under the
same constraints a human scribe works to.

Repo: <https://github.com/April-sus/free-scribe> (private)

## Layout

```
core/        Swift package: scribe rules, filler cleanup, history, search, stats,
             language list, model selection. Shared by macOS and iOS. 70 tests.
macos/       Swift + SwiftUI menu-bar app. Whisper via WhisperKit (CoreML). Works.
windows/     Tauri app (Rust + web UI). Whisper via whisper.cpp. Builds, runs.
             core/ there is the Rust port of the same logic, with matching tests.
ios/         App + keyboard extension. Generated by XcodeGen from project.yml.
             Runs on device. Keyboard not working yet — see "Open bug".
translator/  Rust translation sidecar, shared by macOS and Windows.
docs/        scribe-rules.md is the behaviour contract both platforms owe.
scripts/     generate-notices.py, parity.sh
```

## State by platform

**macOS — working and in daily use.** Menu bar, floating pill, four dictation
styles, permanent transcript history with search and audio re-transcription,
usage stats, sound cues, translation.

**Windows — builds and runs**, but well behind: no history, audio cache, sounds,
search, confirmations or translation. Installers are built by CI (Actions →
Windows installer → artifacts), needing no toolchain on the target machine.

**iOS — app runs on device, keyboard does not.** See below.

## Decisions worth not relitigating

**Everything is local.** No network after model download. This is the product.

**Behaviour must match across platforms**, especially the scribe rules — a school
must get identical transcripts whichever build it runs. `scripts/parity.sh` diffs
the two real binaries; both test suites carry the same cases under the same names.

**One translator, not two.** Apple's Translation framework was used and then
removed: it covered 22 languages against MADLAD's 98 and made macOS and Windows
disagree. MADLAD-400 3B (Apache-2.0) now handles everything, 2.8GB, ~1s per
dictation. NLLB and TowerInstruct are better known and both **CC-BY-NC** — they
would contradict the MIT licence.

**The translator is a separate process**, not a linked library: CTranslate2 is C++
and putting that inside a Swift package is far more trouble than spawning a child.
Does not work on iOS, which has no subprocesses.

**Scribe mode never reaches a language model.** Anything that could suggest a word
is a breach of the rules. Hard-wired, with tests.

## Gotchas that cost real time

- **The simulator lies.** It reports the host Mac's hardware (48GB/492GB, so the
  storage tiering picked the largest model) and overstates memory by ~2x. It also
  ran a Mac-only sysctl happily that crashed instantly on a device.
- **CI can pass for the wrong reason.** The iOS build went green on a runner whose
  Xcode had no FoundationModels at all — the code was compiled out, not checked.
- **A keyboard extension is sandboxed apart from its own app.** Anything the app
  downloads is invisible to it. They share an app group container now.
- **Hardened runtime needs the audio-input entitlement** or macOS denies the
  microphone silently, with no prompt, forever.
- **Whisper hallucinates on silence** — a muted mic reliably produced "you". There
  is an energy gate, calibrated against a real microphone (quiet speech peaks near
  0.016) rather than synthesised audio (0.19), which was the first mistake.
- **Whisper returns nothing for very short clips.** They are padded to two seconds.
- **M2M-100 had no fast tokenizer**, so the tokenisation was hand-written and
  checked against the Python reference. MADLAD ships one, so that code is gone.

## Open bug — the immediate next thing

The iOS **keyboard** fails to load the model:

> Unable to load model … compile the model with Xcode or MLModel.compileModel

The app loads the same model fine (8.6MB at launch, 18.9MB loaded). The likely
cause is that WhisperKit fetched an **`.mlpackage`**, which CoreML must compile into
an `.mlmodelc` before use. Compilation is expensive and may be disallowed inside an
extension's sandbox.

Worth trying, roughly in order:

1. Have the **app** compile the model with `MLModel.compileModel(at:)` after
   download, write the resulting `.mlmodelc` into the shared container, and let the
   keyboard load only that. Compilation then happens where it is allowed.
2. Check whether WhisperKit can be pointed at a pre-compiled directory.
3. If compilation cannot be made to work in an extension at all, fall back to the
   keyboard recording audio and the app transcribing.

Memory is **not** the blocker — that was the fear, and 18.9MB against a ~48-60MB
ceiling settles it.

## How to verify things

```bash
cd core && swift test                      # 70 tests, the shared logic
cd macos && ./build.sh && open 'Free Scribe.app'
cd windows && cargo test                   # the Rust port, same cases
./scripts/parity.sh                        # diffs the two real binaries
```

Headless checks on the macOS binary, no microphone needed:

```bash
'./macos/Free Scribe.app/Contents/MacOS/FreeScribe' --transcribe file.wav
'./macos/Free Scribe.app/Contents/MacOS/FreeScribe' --clean "um so like hello"
'./macos/Free Scribe.app/Contents/MacOS/FreeScribe' --translate "Hello there" lv
'./macos/Free Scribe.app/Contents/MacOS/FreeScribe' --devices
```

iOS, with the phone unlocked and connected:

```bash
cd ios && xcodegen generate
xcodebuild -project FreeScribe.xcodeproj -scheme FreeScribe \
  -destination 'platform=iOS,id=<device-id>' -allowProvisioningUpdates build
xcrun devicectl device install app --device <device-id> <path>/FreeScribe.app
xcrun devicectl device process launch --device <device-id> --console local.freescribe.FreeScribe
```

The app logs its readings with an `[free-scribe]` prefix, so the console gives you
the numbers without reading them off the phone.
